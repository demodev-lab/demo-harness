# Operating Principles Template

프로젝트에서 Layer A의 보편 원칙을 변환한 운영 원칙 문서

---

## 프로젝트 운영 원칙

1. 문서와 코드 변경은 항상 함께 커밋한다.
2. 계약(API/스키마/DB/입력 출력)이 바뀌면 관련 문서를 즉시 업데이트한다.
3. 기존 코드/패턴 재사용을 최우선으로 한다.
4. 임시 코드, 더미 데이터, 디버그 흔적은 남기지 않는다.
5. 완료 보고는 검증 결과가 있을 때만 한다.
6. 실패는 원인 분석 후 하네스에 흡수한다.
7. 새 개념은 먼저 glossary에 정의하고 사용한다.
8. 긴 전역 지침보다 짧은 규칙 + 명확한 문서 링크를 선호한다.
9. 책임 구간을 명시한다(누가 결정하고 누가 실행하는지).
10. 도메인 용어는 팀 합의어를 사용하고 동의어를 금지한다.

## 적용 지침

- 각 항목은 프로젝트 상황에 맞게 조정한다.
- 이 문서를 벗어나는 규칙은 Layer A가 아닌 Layer B/C/D로 승격 또는 보완한다.
- 분기별 또는 실패 패턴이 3회 이상 반복되면 재평가한다.
